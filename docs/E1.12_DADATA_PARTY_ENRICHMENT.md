## Зачем

DaData уже используется в **outreach** (lookup по ИНН → директор, адрес, ОКВЭД → Bitrix). В DELNO enrichment нужен для:

1. **Leads** — квалификация заявок (сейчас `company` — свободный текст, ИНН нет)
2. **Operator** — read-only lookup перед созданием лида
3. **Onboarding (E5.1)** — юр. профиль tenant из ИНН
4. **CRM sync (позже)** — push requisites в Bitrix/amoCRM по паттерну outreach

**Не делаем:** full CRM, дублирование outreach UI, вызов DaData из браузера (ключ только server-side).

---

## Архитектура (delno-api)

По правилам [`delno-api/AGENTS.md`](../delno-api/AGENTS.md): **только через adapter**, без import Python из `outreach/`.

```
delno-api/
  app/adapters/party_lookup.py      # httpx → DaData findById + suggest
  app/services/party_enrichment.py  # normalize INN, cache policy, enrich lead/tenant
  app/models/party_cache.py         # PostgreSQL (не SQLite outreach)
```

**Env** (`/opt/delno/.env`):

- `DADATA_API_KEY` (required)
- `DADATA_SECRET_KEY` (optional)

Ключи можно переиспользовать из `/opt/ava-outreach/.env` на том же сервере.

**Reference для портирования логики:** `normalize_inn`, `extract_party_fields`, `DaDataClient` в `outreach/modules/dadata/__init__.py`.
