Выплаты физическим лицам из 1С и по API

Если выплаты физлицам идут каждый день, ручная загрузка в банк не масштабируется. Нормальный контур: реестр рождается в 1С (или в вашей системе) и уходит в сервис выплат по API. Обратно приходят статусы.

Лендинг: выплаты через API и 1С. Сервис для компаний с объёмом от 5 млн ₽ в месяц.

Зачем API, если есть кабинет

Кабинет нужен на старте и для контроля. API нужен, когда оператор не должен копировать Excel. Типовой поток: документ в 1С → реестр → сервис → статусы в тот же документ.

Без этого бухгалтерия живёт в двух мирах: «учёт» и «банк». Ошибки как раз на стыке.

Что передавать в реестре

  • Идентификатор выплаты в вашей системе (чтобы не задвоить).
  • Получатель: ФИО, карта или телефон СБП.
  • Сумма, назначение, дата.

Канал СБП отдельно разобран здесь: выплаты по СБП. Общая рамка — выплаты физическим лицам.

1С: с чего начинают

  1. Описывают, какой документ 1С считается основанием выплаты.
  2. Собирают тестовый реестр на 10–20 строк.
  3. Сверяют статусы: успех, отказ реквизитов, повтор.
  4. Только потом включают автоотправку.

Зачисление в Quantum Payouts — от 1 минуты, комиссия — от 0,4%.

Права доступа

В кабинете разграничивают, кто видит реестр и кто может его провести. Для МФО, ломбардов и сетей с несколькими точками это обязательное требование, а не «приятная опция».
