# Выпуск раздела «Файлы» на C4B

Подготовлено 17.11.2026. На C4B применено 2026-11-17 (PR #113); см. AGENT_CHANGE_REGISTER. Ветка: `codex/tenant-calendar-origin`, PR #111.

## Факты перед выпуском

- Продовая БД: Alembic `007_agent_tasks_runs_steps`; в ветке добавлены `008_appointments` и `009_tenant_folders`.
- `/opt/delno/docker-compose.yml` не монтирует `/data/tenants` в API. Запущенный `delno-api` также не имеет этого тома. В БД `onboarding_uploads` на момент проверки 0 строк; в контейнере `/data/tenants` нет файлов.
- Канонический `delno-api/deploy/docker-compose.stack.yml` уже содержит `TENANT_FILES_ROOT=/data/tenants` и том `delno-tenant-files`. Продовый compose отличается от него и должен быть исправлен перед запуском API с новой загрузкой файлов.
- Сборка кабинета прошла; API: 431 тест пройден на последнем состоянии ветки; office brokers calendar/conference/files/mail: 7/6/7/8 тестов пройдено. Копия схемы продовой БД успешно обновлена с 007 до 009 в отдельном Postgres.

## Порядок при следующей команде на выпуск

1. Снять резервную копию БД и `/opt/delno` исходников; убедиться, что Cursor не правит те же файлы.
2. В продовый compose добавить `TENANT_FILES_ROOT: /data/tenants`, `delno-tenant-files:/data/tenants` для `api`, а в `volumes:` — именованный `delno-tenant-files`. Проверить `docker compose config`; убедиться, что сохранены все действующие настройки сети и Hermes.
3. Выгрузить код из принятого Git-коммита, выполнить Alembic `upgrade head` на Postgres и проверить `current=009_tenant_folders`. Не запускать миграции с пустой БД до исправления старой пары `001/002` (там дублируется `party_cache`).
4. Пересобрать API, кабинет и изменённые calendar/conference/files/mail brokers. Не трогать телефонию, Mango, Asterisk и VPN.
5. Проверить `/health`, наличие тома через `docker inspect delno-api`, раздел «Файлы» в кабинете. Тестовый пользователь A создаёт папку и файл, скачивает и перемещает его; пользователь B не видит их и не может скачать по ID. Проверить сохранность после `docker compose up -d --force-recreate api`.
6. Проверить отправку выбранного вложения из подключённой почты одной компании и отказ с ID чужого файла. Проверить создание/перенос/отмену встречи и статус внешней синхронизации. При ошибке вернуть предыдущие образы и БД из копии, не удаляя файловый том.

## Не входит в этот выпуск

Генерация DOCX/PDF/PPTX/XLSX, чтение бинарных документов из вкладки, приём вложений из входящей почты и восстановление публичных ботов — отдельные изменения и приёмка. Ссылки сайта на DELNO-ботов выкладывать только вместе с рабочим маршрутом обоих ботов.
