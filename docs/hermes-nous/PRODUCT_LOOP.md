---

## 1. Преимущество DELNO одной фразой

Любой новый владелец компании открывает кабинет и получает **своего** Гермеса, который:

1. **Сам проводит онбординг** — шаг за шагом подключает нужные инструменты (почта, календарь, мессенджеры, телефония, файлы, CRM…).  
2. **Сам собирает и обогащает базу знаний компании** — просит сайт / каталог / текст / файлы, парсит, структурирует, кладёт в DELNO Knowledge, потом дообогащает по ходу работы.  
3. **Потом дирижирует** уже подключёнными тулами по заданию владельца (поручения, research, ответы, расписания) — с субагентами Nous там, где это уместно.

Это не «чат с FAQ» и не «ещё один MCP-список». Это **офисный сотрудник, который сначала сам ставит офис на ноги, а потом в нём работает**.

Именно это отличает нас от типичных «AI secretary / bot builders», где клиент сам копается в интеграциях и сам наполняет KB.

## 3. Цикл владельца (happy path)

```
Регистрация tenant
    → Hermes (Nous) в кабинете: «Давайте настроим ваш офис»
    → Сбор компании (office.build_kb_draft — вместе с владельцем):
         • ссылка на сайт → глубокий crawl (услуги/FAQ/блог/контакты) + поиск в открытом вебе
         • доспросить / дособрать: Telegram, Instagram, VK, MAX
         • каталог услуг / прайс / PDF
         • свободный текст «кто мы / для кого / оффер»
         • уточняющие вопросы по пробелам (часы, цены, аудитория, USP)
         • (опц.) ИНН → DaData enrichment
    → Гермес предлагает структуру KB (профиль, услуги, FAQ, тон, запреты)
         → владелец правит / подтверждает → commit в DELNO Knowledge
    → Чеклист инструментов (только нужные отрасли):
         почта → TG/MAX → календарь → ВКС → телефон → файлы → …
         на каждом шаге: форма секрета DELNO → probe → «готово / что не так»
    → Ready: «офис живой» + health
    → Режим работы: владелец даёт поручения → Гермес дирижирует tools/subagents
    → По ходу: новые факты из писем/звонков/сайта → предложение обогатить KB
```

Frontline (клиенты на телефоне/TG) — отдельно; он **читает** уже собранную KB.  
Owner Hermes — **строит и дирижирует**.

## 4. Что должен уметь Nous-runtime для этого (не DIY-заглушка)

Через scoped DELNO MCP (+ встроенные Hermes web/browser где безопасно):

| Способность | Зачем |
|-------------|--------|
| `office.setup_status` / readiness | видеть дыры |
| `credentials.open_form` + connector probe | подключать тулзы без выдачи паролей модели |
| `office.import_website` / web.fetch+browse | наполнить KB с сайта |
| `upload_knowledge_snippet` / KB write tools | формировать и обогащать базу |
| `phones.*`, mail/calendar/files/conference | шаги онбординга и потом дирижирование |
| `delegate_task` (Nous) | параллельный research / разбор каталога |
| `cronjob` (Nous) + зеркало DELNO | «проверяй заявки / почту» после того как офис готов |
| Progress в UI | владелец видит шаги: «читаю сайт → черновик FAQ → подключаю почту…» |

Секреты — только Vault/forms. Модель не хранит пароли в memory.

## 5. MVP продукта (переопределение относительно §11 плана Codex)

**Не** «сразу cron на заявки» как главный экран.  
**Да** для dogfood tenant:

1. Включить Nous runtime (flag) для одного test tenant.  
2. Владелец в чате: сайт + 2 абзаца о компании → появляется KB-черновик → confirm → поиск по KB работает.  
3. Один коннектор (например Telegram или почта) проходит end-to-end через подсказки Гермеса.  
4. Поручение «найди X / ответь по базе» использует уже собранную KB.  
5. Изоляция: второй tenant не видит эту KB и эти tools.

Cron/заявки — сразу после этого (уже есть смысл: есть KB и каналы).
