# DELNO Crystal Widget — сопроводительное описание

## Что это

Это клиентский виджет DELNO для сайта.

Он должен стать единым интерфейсом общения посетителя сайта с ИИ-сотрудником DELNO:

- голосом;
- текстом;
- с общей историей диалога;
- с подключением к базе знаний конкретной компании;
- с возможностью собирать имя и далее контактные данные;
- с последующей передачей диалога человеку при необходимости.

**Текущая версия — v28.**

В репозитории (`delno-widget/`):

| Файл | Назначение |
|------|------------|
| `index.html` | автоматический вариант (theme auto) |
| `light.html` | вариант для светлого фона |
| `dark.html` | вариант для тёмного фона |
| `assets/crystal-orb-static.webp` | графика шара |
| `INTEGRATION.md` | схема подключения к DELNO backend |
| `README.txt` | краткое описание |

---

## 1. Где должен находиться виджет

**Основное положение:** снизу по центру страницы.

Не справа, не слева.

В закрытом состоянии видны:

1. хрустальный шар;
2. маленькая кнопка текстового сообщения рядом с ним.

Шар — основной элемент голосового взаимодействия.

Кнопка сообщения открывает текстовый чат.

В будущем виджет должен уметь устанавливаться на сторонние сайты DELNO-клиентов через небольшой embed-код.

---

## 2. Поведение шара

### В состоянии покоя

Шар:

- постоянно слегка «дышит»;
- внутри него медленно плавает крупное световое пятно;
- движение должно быть спокойным;
- виджет должен немного привлекать внимание, но не раздражать.

Внутреннее пятно занимает примерно 60–70% диаметра шара.

### Цвет пятна

**На светлом фоне:**

- пятно светлое / белое;
- интерфейс внутри шара тёмный.

**На тёмном фоне:**

- пятно тёмное / графитовое;
- интерфейс внутри шара светлый.

То же правило применяется к: кольцам, статусам, значкам, контурам.

В рабочей версии режим должен быть: `theme = light | dark | auto`

**По умолчанию:** `auto`

---

## 3. Нажатие на шар

При клике / tap:

1. шар быстро и плавно подпрыгивает;
2. текущая продолжительность прыжка — около 0,6 секунды;
3. плавающее внутреннее пятно прекращает движение;
4. появляется отдельное центральное пятно;
5. оно остаётся строго по центру до окончания активного состояния.

После завершения работы:

- центральное пятно исчезает;
- снова появляется плавающее;
- возвращается спокойное «дыхание».

**Важно:** во время Listening / Thinking / Speaking центральное пятно не должно двигаться вообще.

---

## 4. Состояния голосового интерфейса

Основная последовательность:

```
Idle → Listening → Thinking → Speaking → Idle
```

### Listening

- микрофон внутри центрального пятна;
- статус: **Слушаю…**
- вокруг шара расходятся мягкие кольца.

### Thinking

- **Думаю…**
- три небольшие точки внутри шара.

### Speaking

- **Отвечаю…**
- небольшой waveform внутри шара.

При реальном подключении эти состояния должны управляться не таймерами, а фактическим состоянием голосового движка.

---

## 5. Статус над шаром

Над шаром — маленькая минималистичная плашка:

- строго по центру шара;
- компактная;
- меняет ширину под текст (не один широкий контейнер).

Примеры: `Слушаю…`, `Думаю…`, `Отвечаю…`

---

## 6. Кнопка текстового чата

Небольшая speech-bubble кнопка рядом с шаром — отдельное действие.

**Правило:**

- **шар = голос сразу**
- **bubble = текст**

Не делать выбор «Голос / Текст» после нажатия на шар.

---

## 7. Текстовый чат

При открытии:

```
DELNO                         ×
Здравствуйте. Чем могу помочь?
[ Введите сообщение…      ] [➤]
        Работает на DELNO ↗
```

- Поле ввода — настоящий `textarea`
- **Enter** — отправить
- **Shift + Enter** — новая строка
- На телефоне — нормальная клавиатура и кнопка отправки
- textarea увеличивается по высоте при длинном сообщении

---

## 8. Как должен расти чат

Изначально окно маленькое. Контейнер растягивается **вверх** (виджет у нижней части экрана).

При достижении max-height — история прокручивается внутри. На телефоне не занимать весь экран без необходимости.

---

## 9. Логика первого диалога

1. Посетитель задаёт вопрос → DELNO отвечает по KB
2. После первого содержательного ответа — мягко запросить имя
3. Имя сохраняется в сессии

**Не спрашивать имя до ответа на первый вопрос.** Сначала польза.

---

## 10. Какие данные собирать

Постепенно, по сценарию: имя → телефон → email → время → интерес. Не превращать чат сразу в анкету.

## 12. Как связать с DELNO

**Публичный виджет нельзя напрямую подключать к `/v1/operator/chat`.**

Нужен отдельный публичный слой:

- `POST /v1/public/widget/session`
- `POST /v1/public/widget/message`

Подробнее: [`delno-widget/INTEGRATION.md`](delno-widget/INTEGRATION.md)

---

## 13. Создание сессии

```http
POST /v1/public/widget/session
```

```json
{
  "site_key": "PUBLIC_WIDGET_KEY",
  "visitor_id": "UUID",
  "page_url": "https://client-site.ru/page",
  "referrer": "https://google.com/",
  "channel": "web"
}
```

Response:

```json
{
  "session_id": "UUID",
  "widget": {
    "theme": "auto",
    "collect_name": true
  }
}
```

---

## 14. site_key

На каждом сайте клиента — свой публичный `site_key`. Клиентский JS **не передаёт `tenant_id`**.

```
site_key → DELNO backend → tenant → Knowledge → Operator
```

Tenant определяется только сервером.

---

## 15. Отправка сообщения

```http
POST /v1/public/widget/message
```

```json
{
  "site_key": "PUBLIC_WIDGET_KEY",
  "session_id": "UUID",
  "visitor_id": "UUID",
  "message": "Сколько стоит доставка?",
  "visitor": { "name": "Алексей" },
  "channel": "web"
}
```

```json
{
  "message": "Доставка стоит...",
  "next_step": "ask_name"
}
```

## 16. Связь с базой знаний

```
Widget → Public Widget API → Tenant Context → DELNO Operator → Knowledge → Ответ
```

Поиск строго **tenant-scoped**.

---

## 17. Голос и текст — одна сессия

Одна `conversation_session_id` для голоса, текста и handoff человеку. Одна история.

---

## 18. Лид

```
visitor → conversation → name → phone → lead
```

Один lead на посетителя/сессию, не на каждое сообщение.
